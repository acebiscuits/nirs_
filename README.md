# PN-V2 / STFT / MDCT: экспериментальный тракт для диплома

## Что реализовано

- V2 TimePack: 20 000 Hz, физический пакет 400 отсчётов: 320 полезных (16 000 Hz) + 80 PN (20 000 Hz), 50 пакетов/с.
- Физическая длительность полезного PCM: 320/16000 = 20 мс; длительность физического пакета: 400/20000 = 20 мс. **Голос не ускоряется**. На приёмник в наушники идёт **только** восстановленный полезный PCM 16 кГц; PN остаётся исключительно в `rx_wire.wav` для исследования, не поступает в `paplay`.
- STFT `frame_size=640`, `hop_size=320`; MDCT `half_size=320`. Используются реализации из исходного проекта. Каждый спектральный hop получает отдельную маску от номера фрейма и общего ключа. Преобразование использует перекрывающиеся окна; семплы полезного потока НЕ являются независимыми криптографическими фреймами.
- Одинаковый файл ключа на TX/RX. Рандомный nonce и прежний протокол синхронизации удалены из рабочего кода. Внутренний постоянный salt `thesis-static` необходим только совместимости с существующим генератором масок; это **не** меняющийся nonce.
- Три аудиодорожки на RX: `rx_cipher.wav`, `rx_correct.wav`, `rx_wrong.wav`. В последней применяется намеренно неправильный ключ. `--monitor rotate`: попеременное воспроизведение каждого режима по 5 секунд, для субъективного сравнения.
- Тестовый двухсекундный пятичастотный сигнал в начале TX, чтобы сравнить восстановленный сигнал с эталоном. Лог `pilot_check` содержит нормированную корреляцию. `LIKELY_OK` — эвристика, а не криптографическое доказательство: Opus может понизить корреляцию, при `UNVERIFIED` неизвестно, виноват ли ключ, пропуски или кодек. На чистом локальном WAV сигнал проверен. Калибровка перезаписывает первые две секунды реального микрофона/входного WAV; отключается через `--pilot-seconds 0`.
- CSV по всем фреймам, JSONL по смене состояний V2 и диагностике, `summary.json`.

## Требования

Linux, PulseAudio или pipewire-pulse, `pactl`, `parecord`, `paplay`, `python >=3.10`, `numpy`, `scipy`.

```bash
python -m pip install -r requirements.txt
python -c 'import secrets; open("mykey.bin", "wb").write(secrets.token_bytes(32))'
```

На **обеих** машинах должен находиться один и тот же `mykey.bin` (передать его отдельно). Реальные устройства определяются по умолчанию; при необходимости укажите `--mic` и `--speakers` (имена PulseAudio source/sink).

## Запуск

1. Запустить RX и TX. Создаются виртуальные устройства, программы ждут Enter.
2. Переподключить/обновить Телемост; выставить на передающей машине микрофон `TX_Microphone`, на принимающей машине динамики `RX_sink`.
3. **Сначала** нажать Enter на RX, затем Enter на TX.
4. RX получает PN, вырезает его из полезного звука, отслеживает номера фреймов, восстанавливает аудио. В `rx_correct.wav` — результат дешифрования; в `rx_cipher.wav` — исходный зашифрованный полезный сигнал без PN.

Приёмник:

```bash
python main.py --role rx --key-file mykey.bin --out runs/rx1 --listen --monitor rotate
```

Передатчик:

```bash
python main.py --role tx --key-file mykey.bin --out runs/tx1
```

Для прослушивания только расшифрованного сигнала: `--monitor correct`; только зашифрованного: `--monitor cipher`; дешифрования неправильным ключом: `--monitor wrong`. Во всех случаях три WAV записываются независимо. `--listen` включает **реальные** наушники на стороне RX (по умолчанию отключено).

## Автономные испытания без устройств

```bash
python main.py --role tx --key-file mykey.bin --input sample_16k_mono.wav --out runs/tx_test
python main.py --role rx --key-file mykey.bin --input runs/tx_test/tx_wire.wav --out runs/rx_test
```

У `sample_16k_mono.wav` должны быть PCM16, mono, 16 kHz. Во входном RX WAV — PCM16, mono, 20 kHz.

## Ограничения, существенные для диплома

1. Тесты с реальным Телемостом и Opus здесь **не выполнялись**. Локально проверена цепочка WAV → TX → V2 RX. В реальном вызове автоматическая регулировка усиления, подавление шума и преобразование частоты могут менять результаты.
2. Счётчик PN повторяется каждые 64 фрейма (1,28 с); при длинном разрыве связь абсолютного счётчика масок может стать неоднозначной. На коротких потерях V2 восстанавливает счётчик по физической временной шкале. Не считать этот вариант устойчивым к произвольным долгим разрывам.
3. Для STFT/MDCT перекрытие окон и обработка первых фреймов приводят к задержке/пограничным артефактам. После пропусков индексы пересинхронизируются, но данные в соседних окнах могут быть повреждены.
4. `signflip` в существующей реализации — экспериментальный спектральный скремблер. Это не криптографически стойкая или аутентифицированная защита и не гарантирует конфиденциальность.
5. Нет буфера защиты от отставания CPU; долгие паузы Python-процесса могут сорвать real-time. `frames.csv` полезен для выявления потерь.
6. Опция `--operation invert` не использует ключ. Она сохранена ради исходного унифицированного интерфейса.
7. Виртуальные устройства в этом проекте общие для ролей TX/RX; **не** запускайте два экземпляра на одной машине одновременно без адаптации имён устройств.
