# nirs_timepack_v2 — экспериментальная аудиосвязь с PN TimePack

## Что это и чем отличается от старого приложения

Здесь **нет** FULL, CHECKPOINT, QIM, overlay-посылок, chirp и вычитания
синхросигнала из полезного звука. Вместо них используется
`v2_timepack.py`, перенесённый из `test_stand(1).rar` (V2 SuperSpinner
8×8), с исправлением защиты от ложного подтверждения при потере пакетов.

**Тракт:** физический микрофон обычно 48 кГц → `parec --rate=16000`
(ресемплинг внутри PulseAudio) → 320 PCM отсчётов за 20 мс →
преобразование 320 коэффициентов → **TimePack при 20 кГц:**
`320 PCM отсчётов (16 мс) + 80 PN отсчётов (4 мс)` →
`TX_Microphone` → звонок → `RX_sink` → запись монитора при 20 кГц →
корреляция с 64 PN-шаблонами → удаление PN и восстановление номера
кадра modulo 64 → 320 PCM отсчётов при 16 кГц (20 мс) →
дешифратор → физические наушники.

Пакет длится 20 мс и содержит 400 отсчётов. 50 пакетов в секунду.
**Никакой кусок исходной речи не выбрасывается**: полезные 320 отсчётов
ускоренно проигрываются при 20 кГц. Поэтому спектр на передающей стороне
изменяется, и кодек может его исказить. PN в 4 мс — отдельный блок, не
наложенный на речь. На выход в наушники PN не передаётся.

При потере полного пакета V2 восстанавливает номера, но повреждённые /
недостоверные полезные кадры не выдаёт как корректные. Граница ключевой
маски для `stft`/`dct4` определяется индексом кадра **modulo 64**,
поскольку сам PN-пакет не передаёт абсолютный индекс. В результате
ключевые маски повторяются через 1,28 секунды. Это **исследовательский
скремблер**, а не криптографически стойкая система.

## Зависимости

Linux, PulseAudio или pipewire-pulse, `pactl`, `parec`, `pacat`, Python 3.10+,
NumPy и SciPy. Для дополнительного тестирования Opus нужен `ffmpeg`.

```bash
python3 -m pip install -r requirements.txt
python3 -c 'import secrets;open("key.bin","wb").write(secrets.token_bytes(32))'
```

Один и тот же `key.bin` на обоих компьютерах. Он не включён в архив.

## Двусторонний звонок: запустить на КАЖДОМ ПК

```bash
python3 main.py duplex --key-file key.bin \
  --cipher stft --operation signflip --out runs/pcA --duration 60
```

На другом ПК: тот же ключ, шифр и операция, другой `--out runs/pcB`.
В звонке установи **микрофон `TX_Microphone`**, **динамик `RX_sink`**;
в `pavucontrol` проверь, что физические наушники заняты только Python,
а звук браузера/Discord не воспроизводится в обход `RX_sink`.
Отключи шумоподавление, AGC и echo cancellation, насколько возможно;
Discord также может обрывать передаваемые кадры из-за VAD.
После настройки устройств нажми Enter в терминале.

**Клавиши RX** (цифра и Enter):

- `0` — извлечённый зашифрованный PCM (без PN)
- `1` — правильно расшифрованный PCM
- `2` — дешифрование неправильным ключом
- `3` — полная тишина (проверка обходного звука)
- `r` — ротация 0 → 1 → 2 каждые 5 секунд
- `q` — штатный выход

При завершении автоматически выгружаются все `module-loopback`.
Для сохранения чужих loopback-модулей укажи `--keep-loopbacks`.
Кнопка SIGKILL (`kill -9`) не запускает очистку.

## Раздельный TX / RX на двух ПК

TX (из терминала):

```bash
python3 main.py tx --key-file key.bin --cipher stft \
  --operation signflip --out runs/tx --duration 60
```

RX (на другом ПК):

```bash
python3 main.py rx --key-file key.bin --cipher stft \
  --operation signflip --out runs/rx --duration 60 --listen
```

Запускай RX первым. Можно использовать старую форму `python3 main.py run --role rx ...`.

## Локальные тесты без микрофона и браузера

```bash
python3 main.py selftest
python3 main.py selftest --full
python3 main.py selftest --codec
```

`selftest` проверяет V2/PN, сбросы и вставки кадров, короткий полный
TX→RX. `--full` проверяет 6 сочетаний шифра, правильный/неправильный
ключ, позднее подключение и пример внешнего плагина. `--codec` дополнительно
пропускает тестовый PCM через Opus 96 кбит/с (FFmpeg).

Офлайн-тест с собственным WAV:

```bash
python3 main.py tx --key-file key.bin --input voice_48k.wav --out runs/offline_tx
python3 main.py rx --key-file key.bin --input runs/offline_tx/tx_wire.wav --out runs/offline_rx
```

TX принимает моно PCM16 WAV с частотами 16/44,1/48 кГц и т. п. и приводит
к 16 кГц. RX принимает **только** 20-кГц PCM16 WAV.

## Как добавлять новые преобразования

Публичный интерфейс плагина намеренно минимален:

```python
class MyCipher:
    def __init__(self, key: bytes, operation: str, decrypt: bool):
        ...
    def process(self, index: int, pcm320):
        # pcm320 -> 320 finite float32 samples at 16 kHz
        return pcm320
```

TX создаёт объект с `decrypt=False`, RX с `decrypt=True`.
`index` — индекс физического кадра, RX может получить его только
modulo 64 после нового захвата. Алгоритм сам выбирает ключи, внутренние
состояния и поведение на пропусках. Нет `on_sync_event`, `encode_batch`,
`reset`, дополнительных метаданных или наследования, обязательных для плагина.

```bash
python3 main.py tx --key-file key.bin --plugin mymodule:MyCipher --operation custom
```

Полный пример — `crypto/example_plugin.py`. Обязательная проверка:
все три WAV (`rx_cipher.wav`, `rx_correct.wav`, `rx_wrong.wav`) должны
различаться для ключезависимого алгоритма, а `correct` должен походить
на исходную речь после сжатия.

## Преобразования

- `--cipher stft`: реальный rFFT по **320 независимым отсчётам**;
  `signflip`, `shuffle`, `invert` — по внутренним коэффициентам. DC и
  Nyquist не перемещаются. Это STFT с прямоугольным окном и hop=320,
  **а не старый 640/320 перекрывающийся STFT**. Замена необходима:
  обычная перестановка перекрывающихся STFT-коэффициентов не была
  обратима при повторном PCM-анализе.
- `--cipher dct4`: ортонормальный DCT-IV, собственный независимый базис;
  он **не называется MDCT**.
- `--cipher mdct-legacy`: прежняя перекрывающаяся реализация MDCT
  сохранена для сравнительных исследований, но её `shuffle`/`signflip`
  не обеспечивали хорошего восстановления даже без кодека.
- `invert` не зависит от ключа: в этом режиме `correct` и `wrong`
  одинаковы по конструкции.

## Диагностика и ограничения

TX сохраняет `tx_plain.wav` (16 кГц) и `tx_wire.wav` (20 кГц).
RX сохраняет `rx_wire.wav` (весь поток с PN, 20 кГц), а также
`rx_cipher.wav`, `rx_correct.wav`, `rx_wrong.wav` (16 кГц),
`frames.csv` (номер PN, corr, status, причины потерь), `events.jsonl`,
`summary.json` (статистика захвата, потерянные кадры, CPU).

Локально проверены PCM, модель Opus через FFmpeg, потери/вставки пакетов.
**Не проверен** двухсторонний звонок через Telemost/Discord и их встроенные
обработчики сигнала, а также точный ESTOI на реальной речи.
Корреляция 1.0 в автономном тесте относится к синтетическому сигналу
без кодека; 0.998 для Opus 96k — к тому же модельному сигналу.
